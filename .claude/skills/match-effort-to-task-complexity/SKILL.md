## Pattern

Not every task deserves the same level of process overhead. For straightforward operations that can be completed in a single tool call:

- Skip creating todo lists
- Skip writing journal entries
- Skip elaborate planning
- Execute the task directly
- Only add process when complexity warrants it

**Trivial tasks** (direct execution):
- Creating a simple file with known content
- Reading a specific file
- Running a single command with clear output

**Complex tasks** (planning warranted):
- Multi-step workflows with dependencies
- Operations requiring verification across multiple systems
- Tasks with ambiguous requirements needing exploration

## When to Apply

- When the task can be completed in 1-2 tool calls
- When success criteria are immediately obvious
- When there are no dependencies or prerequisites
- When the execution path is completely straightforward

## Anti-Pattern to Avoid

Don't create analysis paralysis by over-planning simple operations. Writing extensive documentation about how to create a "hello world" file wastes time and adds no value.
